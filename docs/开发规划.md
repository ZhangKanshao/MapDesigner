# MapDesigner 首版开发规划

日期：2026-10-20。状态：规划草案，尚未开始实现。

## 目标与假设

开发面向 Windows 的离线地图着色软件，完成“打开地图 → 区域着色 → 配置图例 → 保存工程 → 导出图片”的完整流程。界面使用简体中文，暂定名称 MapDesigner。

当前仓库为空，尚无既有技术栈或代码。首版默认支持 Windows 10/11 x64；交付前应在相应系统实测。首张地图暂定世界国家/地区简图，可在实现前替换为其他行政区地图。

MapChart 的移动应用之外另有网页版，可通过 Windows 浏览器使用。本项目的目标是独立桌面应用和离线本地工程工作流。

## 首版范围

| 模块 | 首版行为 | 验收方式 |
| --- | --- | --- |
| 内置地图 | 提供一张世界国家/地区矢量简图，悬停显示名称 | 断网启动后正常显示；岛屿与多部分区域可共同着色 |
| 画布 | 滚轮缩放、平移工具或空格拖动、适应窗口 | 拖动结束不误触着色；缩放后点击目标正确 |
| 着色 | 选择颜色、单击填充、清除单个区域颜色 | 只修改目标区域；取消着色后恢复默认色 |
| 编辑历史 | 撤销/重做，Ctrl+Z / Ctrl+Y | 着色、清除、图例修改都可恢复；新修改清除重做分支 |
| 图例 | 添加色组、修改名称和颜色、删除色组 | 区域引用色组 ID；修改色组颜色同步更新所属区域 |
| 版式 | 地图标题、背景色、默认区域色、边界显示开关 | 设置在工程重开和导出后保持一致 |
| 工程文件 | 新建、打开、保存、另存为，使用 .mapdesign 扩展名 | 中文路径可用；有未保存修改时关闭/新建/打开会提示 |
| 图片导出 | 导出 PNG，包含完整地图、标题、图例 | 图片不包含按钮、悬停高亮或编辑选框，且不被当前视口裁切 |

图例采用显式色组：区域保存 groupId，色组保存 id、名称、颜色，未分组区域使用默认色。清除颜色即移出色组；删除色组时显示受影响区域数量并确认，确认后这些区域恢复默认色。允许色组同色异名。

PNG 首版提供固定的标准与高清尺寸，输出时复用与编辑器一致的地图构图，缩放与平移仅影响编辑视口。标题和图例使用固定布局，首版不支持自由拖动。字体优先使用本机常见中文字体并验证导出效果。

## 后续范围

- 下一阶段：多选批量着色、区域搜索、更多内置地图、SVG 导出、自动恢复、最近工程。
- 再后续：文本标注、图案填充、用户地图导入、CSV 数据着色。
- 首版不安排：边界或顶点编辑、自由绘制国界、历史地图、GIS 分析、在线瓦片、账号与云同步。

这里的地图编辑指现有区域的外观和分组编辑。若目标包括手绘地形或改动疆界，需要重新规划数据结构与交互。

## 技术方案

推荐 Electron + React + TypeScript + Vite，地图使用 SVG，地理数据通过 d3-geo 投影并生成路径。状态管理优先用轻量方案，例如 Zustand；文件验证使用明确的运行时 schema。

选择理由：首版主要工作是二维交互、表单、矢量着色和文件导出，使用同一套 TypeScript 开发界面与桌面文件服务便于迭代。代价是安装体积与内存占用需要接受。Tauri 可作为更重视包体时的备选，但会增加 Rust 和 Windows 构建环境要求；当前不同时维护两套桌面方案。

模块边界：

- Electron 主进程：窗口、文件对话框、工程读写、导出写盘。
- preload：仅暴露所需的窄接口；启用上下文隔离，界面不直接访问 Node 或任意文件系统。
- 编辑器：工具、图例、项目状态、撤销重做。
- 地图层：地图模板、地理路径、视口、悬停与点击命中。
- 文档与导出层：校验、序列化、版本迁移、生成不含交互覆盖层的 SVG，再栅格化为 PNG。

建议目录：electron/、src/components/、src/editor/、src/map/、src/project/、src/export/、assets/maps/、tests/、docs/。

## 地图数据与工程格式

初步考虑使用 Natural Earth 的低精度行政区数据，独立加工地图资源，不复制 MapChart 的地图资产。数据内置打包，运行时不依赖地图 API。

数据准备阶段必须检查来源、版本、边界表达、名称、区域完整性和分辨率；Natural Earth 是候选来源，不能直接视作满足所有地区展示需求。记录加工脚本和数据来源，确保结果可重建。

统一区域稳定 ID，不以显示名称或可能重复、缺失的 ISO 字段直接作为唯一键。检查 MultiPolygon、孔洞、跨日期变更线与环方向，避免漏色、反向填充或异常跨图连线。

工程采用 JSON 内容，至少包含：formatVersion、mapId、mapVersion、title、groups、regionGroups、样式设置。地图几何保存在内置模板中，工程只保存引用和编辑结果。模板版本固定；升级后仍能找到旧工程所需模板，无法匹配时明确提示，不静默错配。

加载时校验文件大小、字段、版本、区域引用与色值。保存采用同目录临时文件写入后替换的方式，失败时保留原工程。撤销历史不要求跨重启保存，视口状态不计入内容编辑历史。

## 界面草案

顶部工具栏：新建、打开、保存、撤销/重做、导出。

左侧面板：填充/清除/平移工具、当前色组、调色板。

中央：地图画布、标题与图例预览。

右侧面板：图例色组、标题、背景和边界设置。

底部状态栏：悬停区域、缩放比例、保存状态。

## 分阶段交付

以下为单人开发的粗略有效工作日估算，不是固定承诺；地图数据加工和实际系统测试可能调整工期。

| 阶段 | 内容 | 退出条件 | 估算 |
| --- | --- | --- | --- |
| 1 | 桌面骨架、地图数据、SVG 投影与命中验证 | Windows 窗口可运行，地图完整，代表性复杂区域可正确选中 | 1–2 天 |
| 2 | 着色、工具、缩放平移、撤销重做 | 可顺畅完成基础着色流程 | 2–3 天 |
| 3 | 色组图例、标题样式、工程读写 | 保存重开后内容一致，异常文件有可理解提示 | 2–3 天 |
| 4 | PNG 导出、中文与 DPI 检查、Windows 打包 | 无开发环境的测试机可启动并完成全流程 | 2–3 天 |

合计约 7–11 个有效工作日。阶段 1 应尽早生成可运行的 Windows 包，提前发现打包问题。首版交付优先选择 Windows x64 便携包，安装程序和代码签名安排在分发阶段另行评估。

## 验证与完成标准

- 对项目序列化、格式校验、色组变更及撤销重做编写针对性测试。
- 验证编辑 → 保存 → 重开 → 导出的完整流程，重点检查图例和区域颜色一致性。
- 实测中文文件名、取消对话框、无效工程、未知模板版本和写入失败。
- 实测多岛区域、狭小区域、地图边缘及缩放后的点击命中。
- 在标准与高清导出中检查中文、边界、背景、标题和图例，不裁切、不泄漏编辑覆盖层。
- 在 Windows 10/11 x64 的无开发环境机器验证打包结果；至少覆盖 100% 和 150% 显示缩放。
- 首版无需账号，断网后可打开内置地图、编辑、读写工程和导出。
